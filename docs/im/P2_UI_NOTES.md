# P2 UI 实现与验收记录

需求来源为 `P2_UI_SPEC.md`；已完整阅读 `DESIGN_BRIEF.md`、`AGENTS.md`，并查看 02、03、04、14、16、17、19、20、21、22、23、25 的 WebP 稿。实现使用现有 Material 3 主题和原生角色组件。

## 改动范围

- 替换 `ui/im/thread/AgentThreadPage.kt`，新增时间线气泡、输入、空态、工具状态、Notice 组件。
- `RouteActivity` 仅修改 `entry<Screen.Thread>` 的调用，传入 `focusMessageId`。
- 新增 42 个 `im_thread_` 字符串，覆盖 `values`、`values-zh`、`values-zh-rTW`、`values-ja`、`values-ko-rKR`、`values-ru`。使用 `locale-tui set` 写入自行翻译的文本，保留既有资源的内容和格式。
- 数据层、服务、DI、数据库、`ThreadTimeline`、`AgentThreadVM` 文件及其公开 API 均未改动。文档与本目录的验收截图为说明要求的交付物。

## 需要后续阶段处理的契约边界

1. **自动分话题与并行到达顺序**：当前 `RuleSegmentRouter` 在两小时内继续最近未关闭的段，连续的不相关问题不会自动分成不同段。验收通过“换个话题”创建了多个同时生成的段。`GenerationHandler` 会在发起请求时预建助手 `UIMessage`，而 `ThreadTimeline` 按消息 `createdAt` 排序；本机测试中，持久化后的回复按生成开始时刻回到各自问题旁，没有形成稿 02 的按答案到达时刻交错与整批自动引用。UI 按现有时间线如实渲染；需由上游明确回复的到达时间 / 并行批次契约。本次以真实显式回复验证引用颜色和跳转，没有在界面补造自动引用。
2. **失败请求重试**：按照说明选择最后一条 `canRegenerate` 并调用 `regenerate(item)`。两次 401 场景均能移除原错误并发起既有动作，但随后收到通用错误，未恢复成功回复。当前 VM 未提供失败用户消息的专用重试目标 / 重试方法；建议后续确认失败后的最新候选消息与服务会话可定位，并提供稳定的失败请求重试契约。本次保留错误反馈和关闭入口，没有改服务。
3. **历史定位**：VM 没有 `hasMore`、分页加载状态或按消息 ID 定位 API。界面最多追加 20 页，每页等待最早消息键变化（上限 1.5 秒），没有变化便停止；找不到时显示提示。超出该范围的旧消息需要后续定位能力。滚动到顶部仍调用现有 `loadMore()`。
4. **Notice / 撤销 / 工具授权**：Notice 来源与撤销按 P4 预留。需要工具授权或 ask_user 的动作也没有线程 VM 契约，当前只复用展示详情；稿 18 不在本任务要求中。
5. **语音**：点击式开始 / 结束为许可的界面绕行；完整按住、取消和真实服务联调需要 ASR 契约与可用服务配置。
