# Miffan 4.0 IM 模式设计说明

本说明用于生成 IM 模式设计稿（P0），背景与功能范围见 [开发计划](../IM_EXPERIENCE_PLAN.md)。设计稿是灵感与方向参考：最终实现以 Material Design 3、现有主题 token 与 Miffan 原生渲染为准。

## 评审重点

设计稿评审只看 UX 是否 IM 化：信息结构、交互路径、状态反馈、可发现性。配色由用户自定义主题决定，不作为评审项；风格探索的 a/b/c 三个方向均视为同一 UX 的不同主题。完整稿统一沿用方向 a 的中性配色，以免配色干扰交互判断。

IM 交互约定：

- 会话列表为平铺行加分隔线，不使用每行独立卡片，保证一屏的信息密度。
- 同一发送者连续发出的消息合并成组：只在组首显示头像，时间按组或按分隔条显示。
- 所有操作都能通过常见 IM 手势完成：点击进入、长按菜单、左滑回复（时间线）、左滑置顶/不显示（会话列表）。
- 引用条规则：同一批并行回复（多个话题同时进行）中，每条回复都显示引用条，保持一致；单线对话中，回复紧跟其问题时不显示引用条。
- 会话列表左滑的“不显示”只把伙伴从列表移走，聊天记录保留，有新消息时重新出现；真正删除聊天记录在伙伴资料卡中，并需要二次确认。
- “只看这个话题”时，输入框发出的消息自动归入该话题，不再叠加“回复某条消息”条。
- 从伙伴 Tab 点击伙伴进入资料卡，资料卡的主操作是“发消息”。

## 产品气质

- 像一个温暖、轻快的 IM，而不是 AI 工具。用户感觉是在和“伙伴”聊天，看不到模型名、token、参数。
- 安静、留白充足、圆润。信息密度接近微信/Telegram 的聊天页，但更柔和。
- Miffan（会动的饭碗角色）是伙伴的头像与情绪表达，不是装饰插画。

## 视觉基础

- 参考现有界面：`docs/img/miffan-empty-chat.png`、`docs/img/miffan-tool-call.png`、`docs/img/miffan-character-settings.png`。
- 默认配色：浅色背景近白偏冷（#F6F9FC 一类），用户气泡浅天蓝，AI 气泡浅灰蓝；主色可沿用 Material 动态色。
- Miffan Classic：赤陶色圆碗、金黄米饭、碗身上画着简单的脸（两只竖椭圆眼、小嘴）。其他伙伴可用抹茶绿、樱花粉、月光紫、海盐蓝、墨玉等配色的碗。
- 蓝色大肥鱼主题（`docs/assets/branding/miffan-whale-girl.png`）：蓝发、鲸鱼鳍、单侧蝴蝶结的 Q 版头像，只有头部，没有身体。整体蓝色系。
- 圆角大、阴影轻；字体为系统无衬线体；图标为线性圆角风格。
- 画布：Android 手机竖屏，9:19.5 左右，包含状态栏与手势条。

## 不可出现

- 模型名、token 统计、温度等参数、“新对话”按钮、会话列表抽屉、消息分支切换器。
- 把 Miffan 画成有身体或手的形象；去掉碗的轮廓或脸。

| # | 文件名 | 画面 | 必须体现 |

## 流程

1. **风格探索**（已完成）：01 与 02 的 a/b/c 三个方向。用户结论：三者 UX 均达标，配色归入自定义主题。
2. **完整稿**：沿用方向 a 的配色完成 03～15，并按“IM 交互约定”重做 01、02（文件名不带后缀）。
3. **第一轮修正与第二批**：按“第一轮评审修正”重画 01、03、06、07、09、11、12（覆盖同名文件），并完成 16～25。
4. 产物放在 `docs/im/mockups/`，同时在 `docs/im/mockups/README.md` 中列出每张图对应的画面与生成提示词要点。

## 实现备注（第二轮评审）

设计稿 01～25 已通过 UX 评审，以下是还原时需要注意的、未在图中精确体现的约定：

- 12 引导：图中“OpenAI 一键登录”仅为示意。一键登录只用于实际支持 OAuth 的服务商（目前为 OpenRouter），其余服务商走 API Key。
- 17 工具状态：已完成的步骤折叠成一行摘要（如“查了 3 个网页 ›”），只有进行中的步骤展开；回复完成后全部折叠。
- 21 / 24：点击引用条或搜索结果，都跳到时间线中的原消息，并显示同样的短暂高亮与“回到最新 ↓”按钮。
- 21 中原消息上的“原消息”小标签不实现，只保留高亮。
- 16 / 19 中的 Miffan 由原生渲染器绘制，表情分别对应 Eating 与带错误提示的中性静止态，遵循 `docs/miffan/` 规则。
