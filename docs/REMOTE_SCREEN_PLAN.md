# 远程屏幕（云电脑）开发计划

## 目标与边界

在远程工作空间的基础上增加“屏幕”能力：用户可以在手机上看到并操作远程机器的桌面，伙伴（AI）也可以操作同一块桌面。两者看到的是同一个真实桌面，不是两套各自的视图。

第一版支持用户自己的 macOS 机器和 Linux 机器（含 Wayland 桌面）。Windows、RDP、托管云桌面、手机离线后由远端继续执行的常驻 Agent 不在本计划内。

## 已确定的决策

- 同一块屏幕：用户可看可操作，伙伴也可操作。
- 伙伴的 computer use 能力以远端安装的 cua-driver 为核心，不在 APP 内另造截图/点击实现。
- 目标平台：Linux、macOS。Windows 暂不考虑。
- 两个入口：
  - 专业模式：工作空间详情中的“屏幕”页，与文件、终端并列。
  - 轻松模式：伙伴聊天页右上角的“…”替换为电脑图标，点击进入独立的屏幕页。
- 轻松模式提供“给伙伴连一台电脑”的引导流程。
- 第一版纳入 GNOME 与 KDE 的 Wayland 桌面（方案需先验证，见 P2）。
- cua-driver 最低版本 0.34；低于该版本时由引导流程在用户确认后升级。
- 允许“前台演示”模式：用户授权后，伙伴可以把目标窗口切到前台操作，方便观看。

## P0 验证结论（2026-10-07）

在本机 macOS 26（cua-driver 0.34）与 CachyOS + niri Wayland（cua-driver 0.24，经 Tailscale）上完成，代码在 `feature/remote-screen` 分支。

| 项目 | macOS | Linux（niri Wayland） |
| --- | --- | --- |
| 经 SSH exec 运行 `cua-driver mcp` | 可用。TCC 授权由图形会话中的 cua-driver 守护进程持有，SSH 启动的客户端直接复用 | 可用。需注入图形会话环境变量，并设置 `CUA_DRIVER_RS_ENABLE_WAYLAND=1` |
| 伙伴截全屏 | 约 0.5 秒；`max_image_dimension=1280` 时 PNG 约 450 KB | 约 0.5 秒；0.24 不支持尺寸参数，2560×1440 PNG 约 4.2 MB |
| 伙伴操作 | 计算器 `1+2=3`，后台完成，不抢前台；每次点击约 1.6 秒 | AT-SPI 向 zenity 输入文字并点击 OK，结果正确；无窗口级截图 |
| 用户画面（VNC 经 SSH direct-tcpip） | 系统屏幕共享，仅提供 Apple 认证（type 30）；客户端首选 Tight 时服务器仍选择 ZRLE；3600×2338 物理分辨率，整帧约 1 MB；不限帧率时约 44 次更新/秒，终端持续滚动时约 0.8–0.9 MB/s | wayvnc 0.10 可采集 niri 画面，键盘输入有效；Tight + JPEG 使整帧从 5.4 MB（ZRLE）降到 777 KB，静止时 5 秒增量 36 KB |
| 手机端解码（模拟器） | ZRLE 解码 840 万像素约 268 ms；整帧 `setPixels` 每次约 24 ms，是主要瓶颈；堆占用约 90 MB | 同一份代码 |

结论：两条通道在两个平台上都成立，Kotlin 实现 RFB 足够，不需要 JNI。真机性能与 Linux 指针事件尚未验证。

## 架构

### 职责划分：手机与云电脑

伙伴的推理循环在手机上：助手、模型、提供商、审批、聊天记录都在 Miffan 内，模型请求由手机发出。云电脑上的 cua-driver 是被调用的执行器，不运行模型，也不持有 API Key。

因此两边的分工是：

| 云电脑负责 | 手机负责 |
| --- | --- |
| 执行截图、点击、输入、读取无障碍树（cua-driver） | 组装模型请求：系统提示、可用工具、对话历史 |
| 提供与已安装版本一致的 Skill 文本和工具 schema（MCP `resources` 与 `tools/list`） | 把 Skill 与工具交给模型；转发模型的工具调用；把结果和截图交还模型 |
| 发现图形会话环境、启动 VNC 服务（由 APP 安装的启动脚本完成） | 审批、控制权仲裁、截图入库前的压缩、界面展示 |

cua-driver 的 Skill 应从远端读取，不打包进 APP。0.34 通过 MCP `resources/list` 提供 `skill://cua-driver/SKILL.md` 及各平台文档，内容与远端安装的版本一致；0.24 没有该能力，这也是需要最低版本要求的原因之一。手机只决定读哪些部分、放进上下文的哪里。

另一种架构是在云电脑上运行完整的 Agent，手机只做聊天界面。它便于离线继续执行，但需要把 API Key 和助手配置放到远端，与 Miffan 现有的助手模型不一致，留到“远程常驻 Agent”阶段讨论。

### 两条通道，一条 SSH 会话

```
手机 ── 已验证的 SSH 会话（复用远程工作空间的连接池与主机指纹） ──┬─ direct-tcpip / streamlocal → VNC 服务  → 用户画面与输入
                                                              └─ exec: miffan 启动脚本 → cua-driver mcp（stdio） → 伙伴操作
```

- VNC 只监听远端回环地址或 Unix 套接字，经 SSH 通道转发。手机上不监听任何端口（不用 `setPortForwardingL`）。
- 伙伴通道使用 MCP stdio over SSH exec，接入现有 Kotlin MCP SDK 的 stdio transport；每次运行使用唯一的 cua-driver 会话名（macOS 上会话名由守护进程全局持有，结束后不可复用）。

### 远端启动脚本

把与远端环境相关的判断放到远端，手机保持简单。引导流程在远端安装 `~/.miffan/bin/`：

- `miffan-cua`：定位 cua-driver（非交互 SSH 的 PATH 不含 `~/.local/bin`），在 Linux 上从图形会话进程读取 `WAYLAND_DISPLAY`、`DISPLAY`、`DBUS_SESSION_BUS_ADDRESS`、`XDG_RUNTIME_DIR` 等变量并按需开启 Wayland 后端，然后 `exec cua-driver mcp`。
- `miffan-vnc`：按平台启动或确认 VNC 服务。Linux Wayland（wlroots 系与 niri）使用 wayvnc，优先监听 `$XDG_RUNTIME_DIR` 下的 Unix 套接字；X11 使用 x11vnc `-localhost`；macOS 使用系统屏幕共享，不需要脚本启动。
- `miffan-probe`：输出平台、桌面类型、cua-driver 路径与版本、VNC 可用性等 JSON，供引导流程和健康检查使用。

脚本带版本号，APP 升级后可覆盖安装；内容与执行结果对用户可见。

## 设计要求

### 数据模型

- 屏幕属于主机，不属于目录工作空间。在主机上新增屏幕配置：平台、VNC 端点类型（TCP 端口或 Unix 套接字）、启动脚本版本、最近一次探测结果。
- macOS 屏幕共享使用系统账号认证。SSH 使用密钥时需要另存 macOS 账号密码，放入 `RemoteHostCredentialStore`，与 SSH 凭据同样不进数据库、备份和模型上下文。
- 伙伴能力仍通过工作空间绑定获得：助手绑定的远程工作空间所在主机启用了屏幕，即可使用屏幕工具。沿用 `WorkspaceToolTargetSnapshot`，切换绑定或主机身份变化后，旧的工具调用不能落到新目标上。

### 用户画面（VNC 客户端）

- 编码：优先 Tight + JPEG（质量可调），其次 ZRLE、CopyRect、Raw，支持 DesktopSize。
- 渲染只上传变化区域；页面不可见时停止请求更新；限制刷新频率，按网络状况调整 JPEG 质量。
- Mac Retina 的全分辨率帧需要控制内存：见下方“macOS 画面策略”。
- 输入：直接点按与触控板两种模式、长按右键、双指滚动与缩放、软键盘与修饰键栏、输入法文本转 keysym、剪贴板（先支持基础 CutText）。
- 认证：None、VNC 密码、Apple 认证（type 30）。

### macOS 画面策略

系统屏幕共享只能用无损的 ZRLE，并按物理像素发送 Retina 画面。流量取决于画面变化的面积和频率：桌面基本静止、只看伙伴操作时流量很低，滚动长页面或播放视频时最高。第一版不替换 Mac 的 VNC 服务，在客户端做以下处理：

1. 按点分辨率保存画面：Retina 屏（缩放系数 2）在解码时把 2×2 像素合成 1 个，内存从约 34 MB 降到约 8 MB，渲染开销同比下降。手机屏幕宽度通常低于 1800 像素，肉眼差别很小。放大查看细节时再按需请求原分辨率区域。
2. 限制帧率：上一帧画完并且到达间隔后才请求下一帧，跳过中间状态。Wi-Fi 下 15–20 帧/秒，移动网络 5–10 帧/秒，屏幕页不可见时停止请求。滚动类画面的流量会随帧率近似线性下降。
3. 省流模式：请求 16 位色（RGB565），ZRLE 每个像素从 3 字节降到 2 字节；在移动网络下默认开启，可手动关闭。P1 实测（Linux wayvnc 强制 ZRLE，同一桌面）整帧从 2969 KB 降到 764 KB，文字清晰，柔和渐变有轻微色带。
4. 显示本次连接已用流量，移动网络下首次打开屏幕页时提示。

只有在实测证明上述措施仍不够用时，才评估在 Mac 上安装 Miffan 自己的采集程序（ScreenCaptureKit + H.264），它需要额外的签名、TCC 授权和维护成本，放在 P5 之后。

### 伙伴工具

- 不把 cua-driver 的全部工具交给模型：全部 schema 有 150–186 KB。按平台精选一组，以 `computer_*` 命名，由 APP 内部转发给 MCP，并按远端实际返回的 schema 适配参数（例如 `max_image_dimension` 仅在支持时传）。
- cua-driver 最低版本 0.34（提供 Skill resources 与截图尺寸参数），引导流程负责检测并在用户确认后升级。cua-driver 迭代较快，最低版本随验证结果上调。
- 系统提示中放入 Skill 的精简部分和当前平台文档，其余文档通过工具按需读取。
- Wayland 下没有可信的窗口级截图，伙伴使用整屏截图与 AT-SPI；macOS 优先使用窗口截图与无障碍树。
- 截图在入库与发给模型前转为 JPEG/WebP 并限制尺寸。现有 Claude、OpenAI Chat Completions/Responses、Google 提供商都已支持工具结果中的图片，不支持图片的模型收到文字占位。

### 控制权与可见性

- 一块桌面同一时间只有一个控制者。按主机维护控制权状态：空闲、伙伴操作中、用户接管。
- 伙伴操作时屏幕页默认只看；用户触摸即接管，伙伴暂停后续操作，页面显示“交还给伙伴”。伙伴每一步执行前检查控制权。
- macOS 上 cua-driver 默认后台操作，目标窗口可能被遮住，用户在画面上只看到伙伴的光标。聊天中展示每一步的截图。
- 前台演示模式：用户在屏幕页或聊天中授权后，伙伴使用 cua-driver 的 `delivery_mode:"foreground"` 把目标窗口切到前台操作。授权限于当前任务，任务结束或用户接管后失效；切换期间用户的前台应用会被打断，授权时需说明。
- 聊天中显示“正在操作电脑”卡片，带实时缩略图，点击进入屏幕页。

### 权限与安全

- 助手设置新增“允许伙伴操作电脑”，与 Shell 开关分开；审批粒度为每步、每个任务或自动。观察类操作（截图、读树）与动作类操作（点击、输入、启动应用）分开计算风险。
- 首次开启时说明：截图会发送给模型提供商。
- cua-driver 以 capability manifest 限定可用工具，审批由手机承担。
- 引导流程中提示 cua-driver 默认开启遥测，由用户自行决定。
- 远端 macOS 锁屏或停留在登录界面时，伙伴无法操作，需明确提示。

### 入口

- 专业模式：工作空间详情增加“屏幕”页。
- 轻松模式：伙伴绑定了启用屏幕的远程工作空间时，右上角显示电脑图标；未绑定时仍显示“…”。现有“…”只跳转伙伴资料页，与点击头像重复，替换后不丢功能。
- 轻松模式的屏幕页底部保留对话输入条，用户可以边看边给伙伴下指令。

### 引导流程（轻松模式）

1. 添加电脑：地址（含 Tailscale）、用户名、认证方式，核对主机指纹。
2. 探测：运行 `miffan-probe`，显示平台、桌面类型、cua-driver 与 VNC 状态。
3. 准备：在用户确认后安装或升级 cua-driver、安装启动脚本；需要 sudo 的步骤（例如安装 wayvnc）给出命令，由用户执行或在 APP 终端中输入密码。
4. 授权：macOS 需要在系统设置中给 cua-driver 授予辅助功能与屏幕录制权限，打开屏幕共享。用户可以直接在 APP 的屏幕页里远程完成。
5. 测试：显示一帧画面，并让伙伴执行一次只读截图。
6. 绑定到当前伙伴。

## 验收

1. macOS 与 Linux Wayland 两类主机都能在专业模式中查看和操作桌面；断网、切后台、旋转后能恢复或明确报错。
2. VNC 不在手机上监听端口；Linux 上 VNC 服务只对该用户可达。
3. 伙伴能完成“打开应用—输入—验证结果”的任务，每一步截图出现在聊天中；用户触摸后伙伴停止操作。
4. 关闭“允许伙伴操作电脑”后，模型拿不到任何 `computer_*` 工具。
5. 凭据（SSH、macOS 账号）不进数据库、模型上下文与备份。
6. 轻松模式下新用户可以只通过引导流程完成一台电脑的接入。
7. 真机在 Tailscale 与移动网络下的帧率、流量和内存有记录。

## 待定问题

- macOS 画面策略中的帧率档位需在真机实测后确定默认值；省流模式在 Mac 屏幕共享上的收益待实测。
- GNOME Wayland 新版本的系统远程桌面以 RDP 为主，VNC 后端是否可用因发行版而异；如果不可用，GNOME 需要另找画面通道（例如 RDP 客户端）。在 P2 验证后确定。
- cua-driver 遥测与 capability manifest 的默认配置。
