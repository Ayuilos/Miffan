# Miffan 4.0 IM 化体验开发计划

## 目标与边界

把 Miffan 从面向专业用户的 LLM 客户端，扩展为对 AI 原理“无感知”的 IM 式聊天应用：用户完成一次性配置后，像和联系人聊天一样与 Agent 长期交流。现有架构、数据与专业功能全部保留，以“双模式”共存。

本版本包含：IM 外壳与双模式、以 Agent 为单位的连续时间线、隐形分段与智能话题路由、引用回复式的对应关系呈现、Agent 通过对话修改自身设定、设定与记忆的 Git 式版本管理、四个底部 Tab、面向 IM 模式的引导，以及完整的宣发截图与 README 更新。

后续阶段（不在本版本）：Agent 主动消息、多 Agent 群聊、web-ui 的 IM 化改造。

## 已确定的决策

| 主题 | 决策 |
| --- | --- |
| 模式 | 双模式。新安装默认 IM 模式；老用户首次升级时选择，之后可在“我 → 高级”切换。两种模式读写同一份数据，切换不丢失、不迁移任何内容 |
| 聊天单位 | 一个 Agent 一条连续时间线；底层 `Conversation` 成为用户不可见的“分段” |
| 分段 | 自动切段；短时间内互不相关的问题可以并行成多个分段；智能路由（规则 + 轻量模型） |
| 对应关系 | AI 回复与触发消息不相邻时自动显示引用条；用户可主动“回复”某条消息，且该操作强制路由到对应分段 |
| 自我配置 | Agent 可通过工具修改自身设定，必须可溯源到触发的用户消息，并纳入版本管理 |
| 版本管理 | 设定与记忆统一纳入；还原以新版本形式记录，不改写历史 |
| 导航 | 4 个 Tab：消息 / 伙伴 / 发现 / 我 |
| 宣发 | 每个新特性都有指定的宣发截图，用于发布宣传与 README |

## 设计要求

### 工程隔离

- IM 外壳放在独立包 `ui/im/`，复用 `ChatService`、`ConversationSession`、数据层与现有组件；专业模式页面尽量不改动，降低上游同步冲突。
- 角色渲染继续遵循 `docs/miffan/` 规则：页面只传语义状态给 `MiffanMascot`/`AssistantAvatar`。
- 所有新增持久化字段都有默认值，旧备份可以恢复，新备份在旧版本中可以忽略未知字段。

### 显示层：连续时间线

- `AgentThreadRepository` 按 `assistantId` 汇总该 Agent 的全部分段，按消息创建时间交错排列，向上翻时跨分段分页加载。
- 分段边界不显示标题，只显示 IM 式时间分隔条（相邻消息间隔超过阈值才显示）。
- 引用规则：AI 回复的触发消息就是它在分段内的父用户消息，由 `MessageNode` 树推导，无需另存。回复与触发消息在时间线上紧邻时不显示引用；中间隔了其他消息时，回复顶部显示“↩ 你问：…”，点击可以滚动并高亮原消息。
- 同一批并行回复（多个分段同时进行）中，每条回复都显示引用条以保持一致；单线对话中，回复紧跟其问题时不显示。
- “只看这个话题”时，输入框发出的消息直接归入该分段，不经过路由。
- 会话列表左滑“不显示”只隐藏伙伴行，聊天记录保留，有新消息时重新出现；删除聊天记录在伙伴资料卡中，需二次确认。
- 用户主动引用需要新增 `replyTo`（被引用消息 ID + 所在分段 ID），具体存放位置在 P2 设计评审中确定。
- 长按菜单：回复、复制、只看这个话题（把时间线过滤为单个分段）、重新生成（仅限最后一条回复）、更多。
- 消息分支树在 IM 模式中隐藏；编辑只允许改当前活跃分段内的消息。
- 工具调用默认折叠成人话状态（例如“正在查资料…”）；审批改成确认卡片；错误改成人话并提供重试；不显示模型名和 token。
- 正在生成时，消息列表和时间线顶部用 Miffan 表示“对方正在输入”。

### 上下文层：隐形分段与智能路由

- `SegmentRouter` 的决策顺序：
  1. 用户主动引用某条消息：路由到被引用消息所在的分段。
  2. 没有活跃分段，或距离上一条消息超过空闲阈值：新建分段。
  3. 否则用 `fastModelId` 调用一次轻量分类：输入新消息和各活跃分段的摘要，输出“归入某分段 / 新建”及置信度。
  4. 置信度低、超时或失败时，归入最近的活跃分段（宁合勿拆）。
- 路由和“正在输入”动画同时开始，分类超时上限 15s（OpenRouter 实测：空闲 1.6–3s，其他回复并发时 6–8s 以上；8s 仍会截断，回退会把追问归错话题）；用户消息先乐观显示并带“正在输入”，时间戳取发送时刻。
- 路由结果与原因记录到分段元数据和调试日志，便于排查误判。
- 并行分段各自由独立的 `ConversationSession` 生成；同一 Agent 的多个会话复用现有的按 `assistantId` 过滤机制。
- 分段关闭时（空闲超时、token 接近预算、或被新话题取代），用 `compressModelId` 生成滚动摘要，存入分段元数据。
- 新分段注入的上下文：Agent 设定 + 最近 K 个分段的摘要 + 长期记忆 + 按需检索的历史（升级现有的 `enableRecentChatsReference`）。
- IM 模式下，新建 Agent 默认开启记忆。
- 隐藏的“换个话题”入口：强制关闭当前分段，作为 AI 状态跑偏时的兜底。
- 专业模式中，分段显示为普通会话（使用自动生成的标题）。

### 自我配置与版本管理

- 新增统一的版本表 `RevisionEntity`：
  - `subjectType`（ASSISTANT / MEMORY）和 `subjectId`
  - `parentId`，以及完整快照 JSON
  - 作者：USER_UI / AGENT_TOOL / RESTORE / MIGRATION / BACKUP_RESTORE
  - 改动说明
  - 触发来源：分段 ID、用户消息 ID、工具调用 ID
  - `revertOf`（还原时指向被还原的版本）
- 所有修改路径都必须写入版本：界面编辑、Agent 工具、记忆工具、还原、导入。首次启用时为现有 Assistant 和记忆写入 MIGRATION 基线版本。
- 写入时检查父版本是否为最新（乐观并发，类似快进合并），不一致则拒绝并重新读取，杜绝相互覆盖。
- Agent 自我修改工具：
  - 只在本轮由用户消息发起时可用，并强制记录该消息 ID；工具循环中读到的网页或文件内容不能触发修改。
  - system prompt 拆成“用户基础设定”和“Agent 学到的偏好”两层，Agent 只能修改后者及白名单字段（回复风格、称呼等）。
  - 权限类字段（联网搜索、工作区 Shell、MCP、本地工具等）Agent 不能直接修改，只能发起确认卡片，由用户点击确认。
- 呈现：
  - 时间线中，在触发消息下方显示系统提示“Miffan 调整了自己的设定：… · 查看 · 撤销”；记忆改动同样显示，例如“记住了：…”。
  - Agent 资料卡中的“设定历史”，以及“我 → AI 对我的了解”中的“记忆历史”：提供时间线、差异对比、跳转到触发消息、恢复到某版本。
- 备份包含版本历史；保留策略暂定为全量保留，P4 结束时评估体积。

### 四个 Tab

| Tab | 内容 |
| --- | --- |
| 消息 | Agent 会话列表：最近活跃排序、未读角标、置顶、最后一条预览、正在输入状态 |
| 伙伴 | 我的 Agent；推荐模板（翻译官、写作助手、陪聊等）；“添加伙伴”；Agent 资料卡（头像/Miffan、性格、它记得关于你的什么、能力开关、设定历史） |
| 发现 | 绘图、翻译、收藏、文件与工作区、扩展 |
| 我 | 个人资料；AI 对我的了解（全局记忆及历史）；服务商一次性配置；外观与 Miffan；高级（切换专业模式、模型档位等） |

- 模型概念外显为“快速 / 聪明”档位；需要识图等能力时自动选用合适的模型。
- IM 模式引导：服务商配置（复用 OAuth 流程）→ 选择第一个伙伴 → 直接进入时间线。

## 验收

1. 新安装默认进入 IM 模式；老用户升级后看到模式选择；切换模式前后数据完全一致。
2. 已有会话能以 Agent 时间线浏览，并可直接续聊。
3. 1 分钟内发送 3 个不相关问题，生成 3 个并行分段，每条回复都正确显示引用；主动引用能把消息路由到正确分段。
4. 路由模型超时或失败时回退到规则，不阻塞发送。
5. 分段切换后，AI 仍能根据摘要和记忆接续之前的内容。
6. Agent 自我修改设定都能定位到触发的用户消息；非用户发起的轮次无法修改；权限字段必须由用户确认。
7. 设定与记忆的任意版本都能查看差异并恢复，恢复本身也产生新版本；并发修改不会互相覆盖。
8. 备份恢复、导出、搜索在两种模式下都可用；旧备份可以恢复。
9. 10 张宣发截图（中/英 × 浅色/深色）齐全，README 中英文已更新；IM 模式无硬编码文案。
10. 各阶段定向 JVM 测试、数据库迁移测试、`./gradlew test`、`lint`、`assembleDebug` 通过；无法实机验证的部分在交付中列明。
