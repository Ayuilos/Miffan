# 工作空间体验规范

## 目标

工作空间是日常任务入口。用户首先找到要用的空间和文件，再按需要管理连接和权限。保留 Android 原生交互、Miffan 的主题和已有行为，不把技术配置堆在首屏。

参考依据：[ChatGPT Projects](https://openai.com/academy/projects/) 将持续任务的对话、文件与上下文集中在专属空间；[Grok Bot](https://docs.x.ai/grok-bot/overview) 强调从任务协作进入工作。这两者用于参考任务优先、上下文集中、配置按需出现的原则，不照搬其账户、共享计算机或后台运行模型。

## 信息架构

- 聊天侧栏直接提供“工作空间”，原扩展入口继续可用。
- 管理首页：空间 / 主机 / 密钥，单层导航。
- 工作空间页：搜索，全部 / 本地 / 远程，空间列表，清晰的新建入口。
- 标题栏按当前位置提供新建空间、添加主机或生成/导入密钥；不用悬浮大按钮。
- 空间详情：默认文件；连接信息、状态、管理和权限按需查看。
- 聊天选择器：搜索并选择空间，显示当前绑定；管理入口保持可发现。

## 视觉规则

- 使用主题 surface、文字层级和留白，不叠加大面积强调色或装饰性指标卡。
- 每个列表项优先显示名称；类型及主机作为次要身份；状态采用一行摘要。
- 本地/远程始终可辨认；不能仅用颜色区分，也不重复“远程服务器 · 远程”之类标签。
- 完整账户、端口和路径在详情/审批界面可见；主页只保留足够辨认的摘要。
- 主要触控目标至少 48 dp，支持长名称、窄屏、滚动与深浅主题。
- 没有内容和搜索无结果使用不同空态；提供直接的新建或清除筛选动作。

## 关键流程

1. 首次创建：标题栏新建 → 底部面板选择本地或远程 → 必要字段 → 创建后可进入文件。
2. 远程没有主机：创建表单 → 添加主机 → 返回原表单并选中新主机，名称与目录保留。
3. 主机未信任：原位确认指纹入口 → 明确核对 → 测试 → 返回原创建草稿。
4. 需要公钥授权：密钥 → 离线生成/导入 → 复制公钥或备份 → 返回主机配置。
5. 连接失败：显示具体阶段与可执行的检查/重试动作，保留输入，允许退出失败状态。
6. 日常使用：侧栏 → 空间 → 文件；低频配置不抢占主要路径。

## 必须保留的行为

- 审批快照与执行目标校验、长期授权按目标版本生效。
- SSH 主机指纹必须明确确认；重试不能自动信任变化的指纹。
- Shell 能力与逐次审批独立；关闭 Shell 不关闭文件工具。
- “按需连接”不等于持续在线；连接、目录、命令结果分别记录。
- 私钥仅主动查看，设备锁验证和安全窗口保留；手动备份使用系统文件选择器。
- 编辑/创建草稿跨子流程保持，密码与私钥不进入可持久恢复的 UI 状态。
- 本地文件、Rootfs、终端、Skills 和带 area/path 的深链接兼容。

## 验收

- 离线验证页签、搜索、类型过滤、空态及入口回调。
- 离线验证添加主机/确认指纹往返后的远程创建草稿。
- 验证默认进入文件，显式路径与存储区参数不被覆盖。
- 模拟器检查空态、有内容、连接管理、深色主题、窄屏和表单截图。
- 运行现有权限/目标/状态回归测试与构建；使用最终稳定源码生成统一测试包。

本轮完成当前原生本地/远程工作空间的管理与使用体验；不改变现有按需 SSH 执行架构。

## 极简视觉修订

用户反馈第一版仍有配置页的拼凑感，并选择“极简聊天产品风格，少边框、少色块”。因此移除双层下划线标签栏、描边搜索与筛选、悬浮按钮和有色主机卡；统一为单层导航、低对比搜索、平面列表和中性图标。空态隐藏无意义的搜索/筛选；创建类型采用底部面板说明本地与远程的差别。截图验收包含真实共用标题栏，不能只看内容组件。

修订验收：APP 与测试 APK 构建通过，425 项 app JVM 测试、11 项相关 Android UI 回归测试通过；另以 320 dp 实际模拟器视口检查主页与新建面板。主机/密钥列表的菜单和私钥保护流程保留。
