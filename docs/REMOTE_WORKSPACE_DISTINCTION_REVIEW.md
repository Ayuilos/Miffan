# 本地 / 远程工作空间区分研究

日期：2026-09-17。范围：当前工作树的静态代码审查；本轮不修改功能，不进行真实服务器操作。下文区分现状与建议，权限恢复路径的风险尚未做运行时复现。

后续状态：用户已授权实施，本报告保留研究时的现状记录；对应修复、分工与测试结果见 [开发计划](REMOTE_WORKSPACE_PLAN.md) 的“本地 / 远程区分实施分工”。

## 结论

需要同时区分执行位置、连接状态、能力授权和逐次审批。仅换图标或把远程 READY 显示成“已连接”不够。优先修正待审批调用的目标绑定，再统一身份展示与状态模型。

## 优先级最高：审批必须绑定原始目标

静态调用链发现：

1. Shell 调用在 A 工作空间等待审批。
2. 用户把助手绑定切到 B；常规永久授权会重置，这是已有保护。
3. 恢复执行时，ChatService.handleMessageComplete 重新读取当前助手，并按当前绑定创建工具。
4. GenerationHandler 恢复已有 Approved 调用，按 toolName 查找当前工具定义并执行，没有原始工作空间身份比对。

因此，重置未来审批开关不足以保护已经待审批的调用。相同主机 ID 下修改连接目标、重新测试后再恢复调用，也需要防护。这里是代码路径审查结论，尚未通过操作真实主机复现。

建议为所有工作空间调用保存 APP 提供的执行目标快照，并在审批和执行前校验：助手、工作空间、类型、scope、主机配置版本/身份、账户、目录及授权版本。目标变化使旧调用失效并重新发起，不能静默改投新目标。快照不应由模型填写；旧记录缺少快照时也不能自动继续执行。

相关位置：`ChatService.kt` 的 handleMessageComplete/createWorkspaceToolsIfReady/alwaysAllowWorkspaceShell；`GenerationHandler.kt` 的恢复执行分支；`WorkspaceRepository.kt` 的 executeCommand/withRemoteWorkspace。

## 视觉和状态设计建议

- 类型是固定属性：本地用文件夹/设备，远程用服务器；列表、选择器、聊天入口、详情、工具审批使用一致表示，不能只靠颜色。
- 本地/远程列表分组，保留同一工作空间入口；远程主机和 SSH 密钥作为连接配置入口，避免长列表淹没空间。
- 远程身份分行显示：空间名；主机别名与 `user@host:port`；工作目录。聊天保留简短身份，点击展开完整信息。
- 状态拆分：配置状态（缺凭据、待确认指纹）；连接活动（空闲、连接中、操作中）；最近检查（成功/失败、时间、原因）；任务结果（成功、命令失败、结果未知）。
- 当前按需连接架构下，空闲显示“按需连接 · 2 分钟前验证成功”，不能长期显示绿色“已连接”。仅有真实活动会话时显示已连接。
- 主机可连接与目录可访问分别记录。同一主机的一个目录无权限，不应该让所有目录都显示离线。
- 普通操作成功和传输错误更新健康记录；非零退出码不是网络断开，文件不存在不是主机离线。超时/取消后的远程命令可能仍在运行，应显示结果不确定，避免自动重试写操作。
- 提供手动“测试连接”，页面活动时可做有限刷新；不需要为了状态灯默认建立全局常驻连接或后台频繁探测。

## 权限设计建议

将三种概念明确分开：

1. SSH 主机信任：连接的是谁；已信任指纹不代表允许 AI 执行任意命令。
2. AI 能力授权：不启用 / 文件读取 / 文件读写 / 允许 Shell。关闭 Shell 时仍可按授权提供 SFTP 文件工具。
3. 执行审批：允许一次、当前会话、针对该助手与该目标的持续允许。默认逐次审批；本地授权不带到远程，主机 A 的授权不带到 B。

远程 Shell 的实际能力取决于服务器账户；代码只先 `cd` 到选定目录，再执行命令，目录不是命令沙箱。允许 Shell 时，即使文件工具只读，命令仍可能写文件或访问账户可访问的其他目录，因此不能再声称整体“只读”。真正的服务器侧限制需要账户权限或其他服务器侧隔离。

本地继续显示本地环境的权限与共享 Rootfs 影响；远程显示目标账户、目录与实际执行范围，去掉“本助手私有 scope”式承诺。两者都不能声称绝对安全隔离。

审批卡推荐显示：`远程 Shell · 主机别名`、`user@host:port`、工作目录、完整命令、授权持续范围。命令历史保存当时的目标快照，后续改主机名或绑定不应改写历史解释。

不要把字符串黑名单或“看起来只读”的命令识别当成权限保证。对 sudo 的 UI 提示也不能替代服务器权限控制。

## 建议实施顺序与验收

1. **审批目标绑定**：等待审批时切换本地/远程、切主机、改账户/指纹/目录后，旧调用不得在新目标执行；“持续允许”也不能授权错目标。
2. **统一类型和身份展示**：小屏只显示图标时仍能辨认本地/远程；审批前可看到主机、账户和目录。
3. **拆分远程状态**：历史测试通过后断网不能持续声称在线；命令失败不等于离线；目录权限故障不污染其他空间。
4. **分离能力与审批**：远程可只启用文件工具；关闭 Shell 时 AI 不应得到或执行 Shell 工具；跨目标授权互不继承。

实施时补充上述竞态与状态转换测试；现有本地 Rootfs 安装状态与旧配置迁移须保持兼容。
