## 背景：Miffan 是什么

- Miffan 是一个原生 Android LLM 聊天客户端（Kotlin + Jetpack Compose），源码在 `/Users/chenxiansheng/miffan`，只读参考。
- **本地优先**：手机同时是界面、运行时和数据存储，没有自家服务端。
  - 主人明确决定，**暂不规划“常驻的服务端运行时”**。如果某个方案依赖它，请明确标出来。
  - 用户自有电脑可以通过 SSH 当执行器（工作空间、远程屏幕）。
- 轻松模式下，助手叫“伙伴”，像 IM 联系人：
  - 伙伴之间可以互发消息、私聊、开群聊；

## 主人的目标

主人希望 Miffan 更接近 Claude Code、Codex 这类**原生 Agentic** 的架构：skill、工具、配置、子 agent，乃至新建伙伴，都能由 agent 自行提议和扩展，主人负责批准。

主人不想重复造轮子，希望找到当下最好的现成方案、标准或框架。之前已经调研过 oh-my-pi（omp）的 RPC，结论是不合适，主人决定不再沿用。报告在 `docs/research/OMP_RPC_RESEARCH.md`，可以参考它的评判角度，但**不要再围绕 omp 展开**。

## 候选范围

以下只是起点。请自己补充当下值得关注、但这里没列出的方案，也可以剔除明显不相关的。

1. **能力扩展的标准**：
   - Agent Skills 开放规范，看各家采纳情况；
   - MCP 的最新规范，以及“agent 自己编写或注册 MCP 服务”的实践；
   - 插件和扩展的打包格式，例如 Claude Code plugins。
2. **agent 与界面、客户端之间的协议**：
   - ACP（Agent Client Protocol，注意 v1 和 v2 的区别）；
   - AG-UI；
   - Codex app-server 协议；
   - Claude Agent SDK；
   - 其他。
3. **agent 与 agent 之间的协议**：
   - A2A（Agent2Agent）；
   - 其他多 agent 通讯标准。
   - 这一类和 Miffan 的伙伴私聊、群聊直接相关。
4. **能让 agent 自我扩展、自建能力的框架和产品**：
   - Letta（自管记忆）、Goose、OpenHands；
   - OpenAI Agents SDK；
   - 其他。
   - 重点看它们如何让 agent 增加能力，同时把权限交给人。
5. **移动端或本地优先的 agent 运行时**：有没有能在 Android 本机运行、适合嵌入 Kotlin 应用的方案。

## 评判标准（按重要性）

1. **本地优先**：能在手机本地运行，或只需要用户自有设备，不依赖常驻服务端。
2. **权限模型**：能否保留“身份对等，权限不对等”，主人的审批不会被绕过，消息来源可信。
3. **多参与者**：是否适合多个长期伙伴、主人加入的群聊，而不是只有一个 agent 的会话。
4. **自扩展的完整链路**：从提议、预览、审批、安装或启用，到可用、撤销、审计。
5. **生态与成熟度**：规范的稳定性、采纳度、许可证、维护活跃度，以及 Kotlin/JVM 是否有可用的 SDK。
6. **接入成本**：和 Miffan 现有代码（工具、MCP、skill、扩展管理、审批卡、消息来源）的契合度。
