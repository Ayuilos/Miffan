# 伙伴协作开发计划（分组置顶、伙伴私聊、群聊）

## 目标与边界

借鉴 Grok Bot，让轻松模式里的伙伴更像 IM 中的联系人：消息列表可以分组和醒目地置顶；伙伴之间可以互相发消息；之后支持多伙伴群聊。

核心原则是**身份对等，权限不对等**：你和每个伙伴都是聊天的参与者，伙伴之间的聊天与你和伙伴的聊天是同一种东西；但只有你是主人，只有你的话带有权限。

不在本轮：定时任务。Miffan 是本地优先架构，手机同时承担界面、运行时与数据，无法像 Grok Bot 的服务端那样可靠地常驻运行，因此本轮不做。

## 已确定的交互

### 消息列表

- 轻松模式消息列表**取消左滑**，所有操作改为长按，在按住的位置弹出菜单：置顶 / 取消置顶、移到分组…（已有分组或新建）、不显示。
- **置顶区**位于列表顶部：1 个时大头像居中，2～3 个时等距一排，4 个及以上横向滑动；只显示名字，不显示预览；未读以头像角标显示，正在回复通过 Miffan 的语义状态表现。
- **分组**以可折叠的小节标题呈现，组内按最近活跃排序；折叠时标题显示组内未读总数；折叠状态按设备记住。一个聊天只属于一个分组。
- 未分组的聊天直接列在置顶区下方，不加标题；没有建分组的用户看到的就是“原列表 + 置顶区”。
- 长按分组标题：重命名、上移 / 下移、删除分组（成员回到未分组）。
- 分组与置顶的对象是“聊天”：伙伴、伙伴私聊和群聊都可以。伙伴 Tab 使用同一套分组，只显示伙伴。

### 伙伴私聊

- 伙伴 A 联系伙伴 B 时，{A, B} 是一段独立的聊天，列表中显示为叠放头像的“小A · 小B”一行，预览显示最后一句是谁说的。
- 你和 A 的时间线中，在 A 联系 B 的位置显示一行“去找 小B 聊了 · 查看”，点击跳转到 {A, B}。
- 伙伴之间的往来更新列表预览，但不计未读、不发通知。
- 你可以在 {A, B} 中发言：@ 谁就由谁回答；没有 @ 时由最近说过话的伙伴回答（与群聊规则一致）。
- A 第一次联系 B 时，在当时的聊天中弹出授权卡，你同意后按“这一对伙伴”记住；可以在资料卡中收回。
- 伙伴通讯录工具列出可联系的人；你在聊天中 @ 某个伙伴可以提示对方去联系它。
- 第一版只传文字。

### 群聊

- 2～6 个伙伴加上你；@ 提及、轮流发言与主持伙伴、分工交接。细节在第 5 阶段设计评审中确定。

## 架构

### 参与者与聊天

- 参与者：你有一个固定 id；每个伙伴的参与者 id 就是 `assistantId`。
- 有两个及以上伙伴参与的聊天使用新的数据表：
  - `chat`：类型（伙伴私聊 / 群聊）、标题、创建时间。
  - `chat_member`：成员与加入时间。
  - `chat_message`：发送者、内容、引用、权限（是否来自主人）、来源（由哪个伙伴的哪一轮产生）、创建时间。
- 你和伙伴的一对一聊天继续使用现有时间线（`ThreadTimeline` / `ThreadService`），概念上即 {你, 伙伴}。
- 为将来可能的多端同步留路：所有 id 使用 UUID，消息只追加不改写，都带时间戳与发送者。

### 私有视角分段

- 每个伙伴在每段多伙伴聊天中有一个私有视角分段（普通 `Conversation`）。轮到它发言时，把聊天记录按它的视角同步进分段：它自己的话为 assistant，其他所有人的话为带名字的 user（如“[小A] …”“[主人] …”）。
- 生成直接复用 `ChatService`：工具、电脑操作、审批、记忆全部沿用。
- 生成的回复作为该伙伴的发言写回聊天；工具过程不在聊天中展开，只显示一行摘要（与现有“操作了电脑 N 步”一致）。

### 消息来源与主人权限

- 新增 `message_origin` 表（app 内 Room，不改 `ai` 模块的 `UIMessage`），记录私有视角分段与一对一时间线中每条消息的来源：主人、伙伴（含交换 id 与调用链）、系统事件。
- 当前以“最后一条 USER 消息”作为触发者的三处判断（`ChatService` 生成入口与记忆回合、`GenerationHandler` 的修订来源）改为“本轮中最后一条来自主人的消息”。非主人发起的回合没有触发者：
  - 自我修改工具拒绝执行；
  - 伙伴间授权只能由主人确认；
  - 记忆整理标明来源，不把其他伙伴的话记为“对你的了解”。
- 审批卡显示在发生操作的聊天中并发通知，只有你能处理；你不在时挂起等待。
- 未读计数按来源过滤。

### 伙伴之间的消息

- 工具：`list_contacts`（可联系的人：你与已有伙伴）、`send_message(对象, 内容)`。
- 发给伙伴：找到或创建 {A, B}，投递后由 B 生成一轮；同一对伙伴始终使用同一段聊天。
- A 的工具调用最多等待 90 秒并返回 B 的回复；超时返回“B 稍后回复”，B 完成后向 A 的原分段投递一条系统事件“小B 回复了”，唤醒 A 处理并向你汇报。
- 发给你：伙伴把消息直接放入与你的一对一时间线，计入未读并通知（即 4.0 推迟的“主动消息”）。
- 防循环：调用链随消息传递，链上的伙伴不能再被联系；深度最多 2 层；每段聊天每次交换有轮数上限。

### 分组与置顶的数据

- 分组存入设置（随备份走）：有序的 `chatGroups`，每组包含 id、名称与有序的成员聊天 id。不复用专业模式的 `Tag`（一对多语义不同），也不写入 `Assistant`（避免把整理操作记进设定历史）。
- 置顶迁入设置，按置顶先后排序；首次启动把本机 `ThreadListState` 中的置顶迁移过去。
- 折叠状态、已读、不显示仍保存在本机。

## 验收

1. 轻松模式消息列表没有任何横向滑动手势；长按伙伴行、置顶头像与分组标题都弹出对应菜单。
2. 置顶 1 / 2～3 / 4+ 个时布局正确；未读与正在回复状态在置顶头像上可见。
3. 分组可新建、重命名、排序、删除；折叠后未读总数正确；删除分组后成员回到未分组。
4. 分组与置顶在备份恢复后保留；升级后原有置顶不丢失。
5. 伙伴私聊、其他伙伴的话或系统事件都无法触发自我修改、权限授权或“对你的了解”的写入。
6. A 联系 B：首次弹授权卡；90 秒内返回回复；超时后 B 的回复能唤醒 A 汇报；循环与深度限制生效。
7. 伙伴间往来不计未读、不发通知；伙伴主动发给你的消息计未读并通知。
8. 各阶段定向 JVM 测试、数据库迁移测试、`./gradlew test`、`lint`、`assembleDebug` 通过；新文案至少完成中英文。
