# 多伙伴共用一台电脑：操作权方案

## 背景

一台电脑可以分给多个伙伴（`PartnerComputers.bind`，绑到同一个工作区），群聊里被 @ 的成员也会同时开始处理。但现在的仲裁只管“用户 vs 伙伴”：

- `RemoteComputerControl` 每台电脑只有 `IDLE / PARTNER / USER` 三种状态，`PARTNER` 不记录是哪个伙伴。
- `partnerActs` 只在用户接管时拒绝；伙伴 A 正在操作时，伙伴 B 的动作照样放行。
- 锁的粒度是“单个工具调用”：A 点开输入框、B 切走焦点、A 的文字打进 B 的窗口。
- 先结束的那次调用在 `finally` 里清掉 `PARTNER`，另一个伙伴还在动，横幅已经显示空闲。

目标：同一时刻只有一个伙伴动鼠标键盘，别的伙伴知道是谁在用、该怎么办，用户在屏幕页能看到是谁。

## 不变的部分

- 用户永远优先：碰屏幕就接管，“交还”后恢复。
- 观察类工具（截图、读窗口状态、无障碍树）不占操作权，谁都能调用。
- 文件和命令不在本方案内：同一工作区的伙伴本来就共用目录，产物按对话 ID 分到 `.miffan/conversations/<id>/`（提示词约定），shell 按对话隔离。
- cua-driver 连接仍按工作区共用（`RemoteComputerRegistry`）。

## 设计

### 1. 操作权以“一轮回复”为单位

伙伴第一次调用动作类工具时占用这台电脑，持有者记为 `(assistantId, conversationId)`，直到：

- 这一轮生成结束（成功、失败、取消都算）——`ChatService` 在该对话的生成任务结束时调用 `control.release(conversationId)`；或
- 持有者连续 **90 秒** 没有任何动作调用（覆盖等待审批、模型卡住、App 被杀后状态残留），之后别人可以接手。

同一伙伴同一轮内的多次动作不再竞争。只锁单次调用解决不了焦点被抢的问题，所以不做。

### 2. 状态模型

```kotlin
sealed interface RemoteController {
    data object Idle
    data class Partner(val assistantId: Uuid, val conversationId: Uuid, val lastActionAt: Long)
    data class User(val resumeTo: Partner?)   // 交还后恢复给原持有者（如果它这轮还没结束）
}
```

- `partnerActs(hostId, holder, block)`：空闲或已是自己 → 更新 `lastActionAt` 后执行；被别的伙伴持有且未超时 → 返回“忙”；用户持有 → 和现在一样拒绝。
- 动作执行期间单独记一个 `acting` 标记，只用于横幅转圈，不再参与“谁持有”的判断，解决 `finally` 提前清状态的问题。
- 占用和释放都写现有审计回调。

### 3. 被拒绝时伙伴怎么做

返回给模型：

```json
{"status":"busy","holder":"小 A","reason":"小 A 正在使用这台电脑。","next":"不要重试动作；先做不需要操作电脑的部分，或告诉用户你在等小 A 用完。"}
```

**建议：立即拒绝，不在工具内排队等待。** 排队会让 B 的工具调用挂几分钟，审批卡片、超时、取消都会变复杂；立即拒绝让模型自己调整，用户也能直接看到原因。群聊里主持伙伴分工时，提示词补一句“同一台电脑同时只能一个人操作，需要电脑的步骤请串行安排”。

待定（需要你决定）：B 被拒后，A 这轮结束时是否在 B 的对话里自动提示“电脑空出来了”。建议先不做，看实际使用里是否经常发生。

### 4. 界面

- 屏幕横幅：从“伙伴正在操作”改成“小 A 正在操作”，带头像；用户接管时仍是“你正在操作 · 交还”。
- 伙伴 B 的屏幕页（`PartnerScreenPage`）在 A 持有时显示“小 A 正在使用这台电脑”，不显示 B 在忙。
- “我的电脑”里的屏幕页（`Screen.ComputerScreen`）现在 `partnerBusy` 恒为 false，改为直接读 `RemoteComputerControl` 的持有者，同样显示是谁。
- `partnerBusy` 不再从某一个伙伴的最新消息推断，统一来自控制状态，保证几个页面一致。

## 不覆盖的情况

- 电脑上别的程序同时在用 cua-driver（例如电脑上的 Claude Code 定时任务、另一台手机上的 Miffan）：手机端无法仲裁，保持现状。
- 专业模式下同一台主机的不同工作区：按主机加锁，所以它们之间同样互斥（这是对的，桌面只有一个）。

## 分期与验收

1. **P1 数据层（我）**：新状态模型、按轮持有、90 秒超时、生成结束释放、`busy` 结果、审计；单测覆盖：两伙伴交错调用、用户接管后交还给原持有者、超时接手、生成取消后释放。
2. **P2 界面（我）**：三处横幅/屏幕页显示持有者；6 种语言文案。
3. **P3 模拟器验收**：用脚本化假 LLM 在群聊里 @ 两个都绑了同一台电脑的伙伴，确认第二个收到 `busy`、屏幕横幅显示正确名字、第一个结束后第二个能接手；真实模型在 CachyOS 上跑一次。
