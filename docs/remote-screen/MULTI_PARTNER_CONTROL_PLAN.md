# 多伙伴共用一台电脑：操作权方案

## 背景

一台电脑可以分给多个伙伴（`PartnerComputers.bind`，绑到同一个工作区），群聊里被 @ 的成员也会同时开始处理。但现在的仲裁只管“用户 vs 伙伴”：

- `RemoteComputerControl` 每台电脑只有 `IDLE / PARTNER / USER` 三种状态，`PARTNER` 不记录是哪个伙伴。
- `partnerActs` 只在用户接管时拒绝；伙伴 A 正在操作时，伙伴 B 的动作照样放行。
- 锁的粒度是“单个工具调用”：A 点开输入框、B 切走焦点、A 的文字打进 B 的窗口。
- 先结束的那次调用在 `finally` 里清掉 `PARTNER`，另一个伙伴还在动，横幅已经显示空闲。

目标：同一时刻只有一个伙伴动鼠标键盘，别的伙伴知道是谁在用、该怎么办，用户在屏幕页能看到是谁。

## 不变的部分

- 用户永远优先：碰屏幕就接管，“交还”后恢复。
- 观察类工具（截图、读窗口状态、无障碍树）不占操作权，谁都能调用。
- 文件和命令不在本方案内：同一工作区的伙伴本来就共用目录，产物按对话 ID 分到 `.miffan/conversations/<id>/`（提示词约定），shell 按对话隔离。
- cua-driver 连接仍按工作区共用（`RemoteComputerRegistry`）。

## 设计

### 1. 操作权以“一轮回复”为单位

伙伴第一次调用动作类工具时占用这台电脑，持有者记为 `(assistantId, conversationId)`，直到：

- 这一轮生成结束（成功、失败、取消都算）——`ChatService.launchGenerationJob` 结束时调用 `control.release(conversationId)`；或
- 持有者连续 **90 秒** 没有开始或结束任何动作，之后别人可以接手；正在执行的动作期间永远不会被接手。

同一伙伴同一轮内的多次动作（包括并行调用）不再竞争。同一个伙伴在另一个对话里（例如群聊视角）算另一轮。只锁单次调用解决不了焦点被抢的问题，所以不做。

等待审批时生成会暂停（`GenerationHandler` 遇到待审批工具就结束这一轮），所以等审批期间电脑是空出来的；用户批准后继续执行时重新占用，若这时被别人占着就收到 `busy`。不让一个等人审批的伙伴长时间锁住电脑。

### 2. 状态模型（已实现）

每台电脑一份 `HostControl(holder, lastActionAt, acting, user)`，在一把锁内修改：

- `partnerActs(hostId, holder, block)` 返回 `Done / UserHolds / Busy(holder)`：用户持有 → 拒绝并记入 `waiting`（和以前一样）；别的轮次持有、且正在执行或未闲置满 90 秒 → `Busy`；否则成为持有者并执行。
- `acting` 计数只表示“此刻有动作在跑”，`states` 仍据此给出 `PARTNER`，界面暂时不变；持有者通过新的 `holders` 流公开，P2 用它显示名字。
- 用户接管时持有者保留；交还时给持有者重新计 90 秒，所以长时间接管后电脑仍回到原来的伙伴。
- 占用/释放不单独写审计：每个动作本身已有记录，再记占用只是噪音。
### 3. 被拒绝时伙伴怎么做

返回给模型：

```json
{"status":"busy","holder":"小 A","reason":"小 A 正在使用这台电脑。","next":"不要重试动作；先做不需要操作电脑的部分，或告诉用户你在等小 A 用完。"}
```

**建议：立即拒绝，不在工具内排队等待。** 排队会让 B 的工具调用挂几分钟，审批卡片、超时、取消都会变复杂；立即拒绝让模型自己调整，用户也能直接看到原因。群聊里有两个以上成员绑定同一台可操作的电脑（远程、已设置屏幕、电脑操作未关闭）时，群提示词补一句“它同一时间只能由一个伙伴操作；分工时把要操作这台电脑的步骤交给一个人，或等前一个用完再安排”。

待定（需要你决定）：B 被拒后，A 这轮结束时是否在 B 的对话里自动提示“电脑空出来了”。建议先不做，看实际使用里是否经常发生。

### 4. 界面

- 屏幕横幅：从“伙伴正在操作”改成“小 A 正在操作”，带头像；用户接管时仍是“你正在操作 · 交还”。
- 伙伴 B 的屏幕页（`PartnerScreenPage`）在 A 持有时显示“小 A 正在使用这台电脑”，不显示 B 在忙。
- “我的电脑”里的屏幕页（`Screen.ComputerScreen`）现在 `partnerBusy` 恒为 false，改为直接读 `RemoteComputerControl` 的持有者，同样显示是谁。
- `partnerBusy` 不再从某一个伙伴的最新消息推断，统一来自控制状态，保证几个页面一致。

## 不覆盖的情况

- 电脑上别的程序同时在用 cua-driver（例如电脑上的 Claude Code 定时任务、另一台手机上的 Miffan）：手机端无法仲裁，保持现状。
- 专业模式下同一台主机的不同工作区：按主机加锁，所以它们之间同样互斥（这是对的，桌面只有一个）。

## 分期与验收

1. **P1 数据层（我，已完成）**：新状态模型、按轮持有、90 秒超时、生成结束释放、`busy` 结果、群提示词；单测覆盖：两伙伴交错调用、同轮并行动作、用户接管后交还给原持有者、超时接手但不在动作中途接手、失败的动作也会结束、同一伙伴另一对话、群提示词条件。
2. **P2 界面（我，已完成）**：三处屏幕页的横幅统一读 `RemoteScreenVM.holder`，显示“名字 正在操作这台电脑”（6 种语言）；`RemoteScreenScaffold` 去掉 `partnerBusy` 参数，伙伴屏幕页不再从自己的消息推断。没加头像：横幅已有转圈，名字足够区分。
3. **P3 模拟器验收**：用脚本化假 LLM 在群聊里 @ 两个都绑了同一台电脑的伙伴，确认第二个收到 `busy`、屏幕横幅显示正确名字、第一个结束后第二个能接手；真实模型在 CachyOS 上跑一次。
