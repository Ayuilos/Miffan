# P2 UI 实现说明

## 已完成

- 基于本工作树已重建的 `feature/remote-screen-ui` 实现，起点与 `feature/remote-screen` 同为 `311114aa`。保留 P1 及后续的键盘队列、SUPER、远端光标等实现。
- 连接方式按「自动（推荐） / TCP 端口 / Unix 套接字」排列。自动方式保存 `RemoteScreenEndpoint.Helper`，隐藏端口/路径输入，说明脚本位置、账户隔离与 SSH 通道。未启用屏幕的主机默认选择自动，但启用开关仍关闭；已启用的主机保留保存的方式。
- 设置对话框增加环境检测区块，显式点击后经 `WorkspaceVM` 委托 `probeHost`，显示进度和本地化错误。`NO_WORKSPACE` 提示先创建远程工作空间。
- 检测结果按系统/架构、桌面会话、屏幕服务、剪贴板和 cua-driver 展示，带正常、需要处理、不支持三种状态图标和无障碍说明。未登录桌面、未打开 macOS 屏幕共享、缺少 Linux VNC/剪贴板工具、cua-driver 未安装/版本不足均有对应引导。
- Wayland 提供 wayvnc、wl-clipboard，X11 提供 x11vnc、xclip 的 Arch 与 Debian/Ubuntu 安装命令；命令可复制，复制后有确认文字。GNOME/KDE 检测结果附支持仍在验证的说明。已安装但未运行的普通 VNC 服务显示为正常，说明打开屏幕时会自动启动。
- cua-driver 安装/升级先显示独立确认框，包含与仓库一致的完整命令（升级路径采用相同的 shell 引号规则）、远端下载/安装来源及 macOS 辅助功能/屏幕录制授权说明。只有确认按钮会发起安装；重复请求、错误升级路径与旧主机修订的检测结果不能再次发起操作。
- 检测/安装状态由 `WorkspaceVM` 按主机保存，旋转不会丢失正在运行的安装。安装期间显示可能需要几分钟的提示，并禁用设置编辑、保存、取消、返回和外部点击关闭。安装成功、失败或抛异常后均自动重新检测；安装结果/最后输出与再次检测的错误分开保存，避免后者覆盖前者。
- 屏幕页按 `RemoteScreenProblem` 区分配置不完整、无桌面会话、缺 VNC 服务及启动失败。分别提供设置、重试、复制安装命令与可折叠日志。普通异常和未单独定义的 unavailable 原因保留 P1 的操作选择。
- 新增 43 组 `workspace_screen_` 英文/简体中文字符串，其他语言使用资源回退。仅这些新增英文键沿用 P1 的逐键 MissingTranslation 标注，不改动其他语言或全局 lint 设置。

## 没做

- 未修改 `workspace` 模块、数据层、`RemoteScreenVM`、远端脚本、数据库或依赖注入；不包含伙伴控制、轻松模式入口及 GNOME/KDE 远端方案验证。
- 未连接远程机器、模拟器或真机；未实际安装软件或执行复制出的 sudo 命令。
- 不自动切换认证、填写密码或开启屏幕。检测按钮会调用已有 API 安装/更新 Miffan 小脚本，cua-driver 另行确认。
- 安装/检测状态为 ViewModel 内存状态，支持旋转，不保证进程被系统终止后的恢复。未保存的设置草稿和未确认的安装提示不跨旋转恢复；密码继续不进入 saved state。

## 需要主代理真机确认

1. 未启用/已启用主机分别默认自动/保留端点；自动、TCP、Unix 的保存与回读，以及 P1 密码保留和保存后重连。
2. macOS、Wayland、X11 的真实检测数据与图标状态，未登录桌面、无工作空间、缺软件和 GNOME/KDE 提示；复制命令是否完整。
3. 安装与升级确认框的命令、来源与权限说明在小屏/横屏可读；取消不执行操作，确认后不能通过返回/外部点击关闭。安装期间旋转后进度与关闭锁定仍正确。
4. 实际安装成功、失败、超时、断网时的输出末尾与自动重新检测；重新检测失败时不丢失此前安装结果。
5. `NO_GRAPHICAL_SESSION` 的重试、`NO_VNC_SERVER` 的复制命令/设置双入口、`VNC_START_FAILED` 的日志展开/收起；恢复条件满足后能重连。检查长日志与环境列表的滚动不会挤掉操作按钮。
6. P1 键盘队列、SUPER、光标形状、手势及生命周期行为在新增设置和错误面板之后保持正常。

## 对接口的建议

- 由仓库暴露安装/升级的命令描述，避免确认文案中的命令拼接与执行实现随以后版本更新发生偏差；本次 UI 函数严格匹配现有实现，并有引号测试。
- 为主机级 probe/install 提供预期 `connectionRevision` 参数，在实际借用 SSH 会话时验证。UI 已拒绝旧修订的检测结果并固定确认时的路径，但现有 hostId 接口无法覆盖确认后、仓库开始执行前的身份变化窗口。
- 安装接口若提供阶段/输出流与明确的超时结果，可显示更具体的进度，并区分远端非零退出、超时和 SSH 失败；当前按现有 outcome/异常显示并保留输出。
- `NO_VNC_SERVER` 若携带桌面名（或完整探测快照），屏幕页也可在未打开检测面板时准确显示 GNOME/KDE 的验证状态；目前异常 detail 仅有会话类型，设置检测结果可显示桌面提示。
